01Findings

Finding.Validate() is a 137-line god-function

Single function in finding_validate.go:10-137 validates 15+ finding fields. Cyclomatic complexity 32 (gocyclo threshold 25). Behavior is correct but the function is a barrier to extension: adding a new field means modifying the largest function in the codebase. Already noted in TODO_LIST from code-quality-scan.

makezero linter produces 4 false positives

Across merge.go:72, finding_methods.go:30,51, pipeline/pipeline.go:48, lsp.go:212. All use make([]T, len(x)) with non-zero initial length for direct indexed assignment. The linter wants make([]T, 0, len(x)) + append. Both patterns are correct; the current one is more readable and avoids append's bounds checks. Noise that obscures real issues.

Reference issues already documented elsewhere

This review confirms (does not duplicate) issues already in TODO_LIST.md from earlier skills: branded primitive types (data-model-review), FindingProcessor → FindingTransformer rename (naming-review), pipeline/ subpackage split (architecture-review), Position sentinel unification (data-model-review v2.0).

02Issue Cards

Important · Type-safety debt

Position zero-value lies about Offset

position.go:23-29 · cascades into Range, Finding.Related, FixEdit

Position{} has Offset=0 (valid byte position!) but File="" (invalid). IsZero() returns false. Every consumer must remember HasOffset() rather than offset>0. Documented in AGENTS.md but still bites newcomers.

Fix (v2.0, breaking) Adopt Option[int] generic for all optional Position fields. Documented as P1 in data-model-review.
Important · Concurrency footgun

SeverityAliases is a mutable global map

severity.go:181

var SeverityAliases = map[string]Severity{...} is documented as consumer-mutable. Concurrent read-after-write panics on Go maps. P5 in data-model-review.
