00Summary

go-finding is a well-engineered, cleanly decomposed multi-module Go library. The Unix-style module split (Core stdlib-only → Pipeline → Analysis → CLI) is genuinely good architecture, and the validation, error-wrapping, and test discipline are far above typical Go projects. There are no build, vet, or test failures.

However, the review surfaced one latent correctness bug (the fix applier returns its input instead of applied findings), a performance lie in the interval index doc, several silent-data-loss paths in SARIF/LSP conversions, a handful of type-safety gaps (a branded FilePath type that the one struct that needs it ignores), and a recurring pattern of lying names and predicates (IsValid that returns true for invalid values, "adjacent" functions that mean "coincident").

The bottom line Ship-ready foundation with solid bones. Fix the 7 critical/high items first — especially the ApplyWithDetails return bug and the IntervalIndex doc/perf claim. Then work the type-safety and data-loss items in the medium tier. The low tier is polish.

◆What's already excellent

Acknowledging the strong work before the criticism — these patterns should be preserved and extended.

+
Unix-style module decomposition is the real deal Core is stdlib-only in production; Pipeline/Analysis/CLI compose via replace directives. Clean dependency direction, dual go.work + replace strategy. Each module does one thing well.
+
Centralized, composable validation with errors.Join finding_validate.go delegates to 6 per-field sub-validators, each <10 complexity, collecting all errors before reporting. Idiomatic and actionable.
+
Consistent, contextual error wrapping Nearly every error path uses fmt.Errorf("...: %w", err) with detector name / file path / iteration number. Sentinel errors enable errors.Is/errors.As.
+
Branded primitive types prevent ID/Rule/Tool mixups ID, RuleName, ToolName are distinct string types with compile-time safety. JSON marshals as plain string. Length-prefixed hash ID prevents collision attacks.
+
FixProvider chain is clean and extensible FixProvider interface + optional lineIndexAware for lazy O(1) line-index lookups. goast.Provider demonstrates real drop-in extensibility.
+
Security-conscious path handling groupFindingsBySafePath resolves symlinks + prefix-checks against root to prevent path traversal. Correct and deliberate.
+
MergeIter streaming design Uses Go 1.23 iter.Seq[Finding], clones on yield, doesn't hold locks across reports, pre-sizes dedup map. Functional-options pattern is idiomatic.
+
Thorough sentinel-value documentation Position/Confidence/FixStrategy docs explain why the design is non-obvious (the Offset: -1 sentinel, 0 means unset). This prevents regression.
+
go-output adapter boundary is clean The go-output dependency is isolated in output_adapter.go; the rest of the CLI never imports it. Root finding package stays dependency-free.

01Critical & High findings

Blocking or near-blocking issues — correctness bugs, data loss, race conditions, and performance lies. Fix these first.

Critical · Correctness bug

ApplyWithDetails returns its INPUT, not the applied findings

pipeline/fix_applier.go:86-93

ApplyWithDetails calls ApplyWithShiftMap and discards the returned appliedFixes slice (second return value is _), then returns the unfiltered input fixes. The doc promises "the list of successfully applied findings" but returns every input finding regardless of whether it was applied. The only test passes nil, masking the bug. 

// BUG: discards appliedFixes, returns input
applied, _, _, err := a.ApplyWithShiftMap(ctx, fixes)
return applied, fixes, err   // should be: appliedFixes
Fix: Capture the second return value and return it. Add a test with non-nil input where some fixes fail, asserting the returned slice contains only the successfully applied findings.
Critical · Lying doc & latent perf bug

IntervalIndex claims O(log n + k) but is O(n + k)

interval_tree.go:15,44-66 · affects correlate.go

The type doc claims "efficient O(log n + k) overlap queries," but Query binary-searches the cutoff, then does for i := range cutoff — an O(cutoff) linear scan. Worst case (all intervals start near 0) every query scans the whole array: O(n + k), not O(log n + k). This propagates into Correlate, which is effectively O(n²) worst case. Also: the file is named interval_tree.go but contains a sorted slice, not a tree.

Fix: Either implement a real augmented interval tree (max-end field per node), or correct the doc to "O(n + k) — acceptable for typical finding counts" and rename the file to interval_index.go. The honest linear scan is fine at current scale; the lie is not.
Critical · Type-safety gap

Branded FilePath defined but Position.File is plain string

branded_types.go:19 · position.go:25

FilePath exists specifically to prevent mixing file paths with arbitrary strings, but the one struct where it matters — Position.File — uses string. ParsedID.File uses FilePath (id.go:90), so the same concept is typed in one place and untyped in another. Split-brain.

Fix: Change Position.File to FilePath. JSON marshals identically. Audit all constructors (Pos, NewRange, FromLSP, SARIF import) for compatibility.
Critical · Lying predicate

Position.IsValid() returns true for "not set" values

position.go:31-34

The docs say Line == 0 means "not set," yet IsValid() checks p.Line >= 0 — so a position with Line: 0 ("not set") is reported valid. HasLocation() correctly requires Line > 0. Two predicates on the same type give contradictory answers about the same concept.

Fix: Either make IsValid() require Line > 0 (and audit callers), or rename it to HasFile() to honestly describe what it checks.
Critical · Lying names

columnAdjacent / offsetAdjacent mean "coincident," not "adjacent"

range_overlap.go:95-110 · also range.go:163 & range_overlap.go:108

"Adjacent" means "next to." These functions return true when the two values are equal. Any caller reading the name will reason incorrectly. Related: r.End.Offset > 0 excludes byte offset 0, which the rest of the codebase (and the Position docs) treat as a valid offset — a range ending at the very start of a file is mishandled.

Fix: Rename to columnCoincident/offsetCoincident (or implement real adjacency with diff == 1), and change > 0 to >= 0 for offset checks.
High · Silent data loss

IsAutoFixable() disagrees with HasFix() on empty FixStrategy

finding_methods.go:106-108 vs 87-100

HasFix() normalizes FixStrategy == "" to none (matching the documented convention), but IsAutoFixable() does not — it returns false for the empty string. Two methods, two answers about the same concept. Also: Equal() normalizes FixStrategy but not Confidence, so Finding{Confidence:1.5}.Equal(Finding{Confidence:1.0}) is false even though both clamp to 1.0.

Fix: Call NormalizeFixStrategy() in IsAutoFixable(). Make Normalized() clamp Confidence too (currently only normalizes FixStrategy). Normalize consistently in Equal() or not at all.
High · Silent data loss

SARIF/LSP conversions silently drop data

sarif_export.go:30-34 · sarif_import.go:99-108 · lsp.go:69-119

Three independent loss paths: (1) ToSARIF drops all suppressed findings — SARIF has native suppressions arrays, so this is unnecessary data loss with no includeSuppressed option. (2) findingFromSarResult keeps only the first fix when a result has multiple. (3) ToLSP discards ID, Category, Tags, Confidence, Suppression, Snippet, BeforeCode/AfterCode — and FromLSP regenerates the ID, breaking Diff/Correlate across LSP boundaries.

Fix: Emit SARIF suppressions arrays instead of dropping. Accumulate multiple fixes or document the truncation loudly. For LSP, persist the original ID in a property bag so round-trip is stable; document every field that is lossy.
High · Public API defect

Registry sentinel errors are unexported — can't errors.Is

registry.go:13-14

errDetectorRegistered and errUnknownDetector are unexported, so external callers of the public DetectorRegistry cannot use errors.Is to distinguish "already registered" from "unknown." For a type whose entire purpose is the public extensibility point, this defeats the error contract.

Fix: Export as ErrDetectorRegistered / ErrUnknownDetector. This is a non-breaking additive change.
High · Race condition

file_backup SetEnabled/IsEnabled not synchronized

pipeline/file_backup.go:47-49

enabled is read without a lock in IsEnabled() and written without a lock in SetEnabled(), while Backup/Restore/ RollbackAll call IsEnabled() concurrently from multiple goroutines.

Fix: Guard with the existing mutex, or switch to atomic.Bool.
High · CLI robustness

No signal handling — Ctrl+C doesn't cancel the pipeline

cmd/go-finding/main.go:183

ctx := context.Background() has no signal handler. Users pressing Ctrl+C get no response until the pipeline's internal timeout fires. The -timeout flag configures the inner pipeline timeout, not the outer context.

Fix: signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM). One line, large UX improvement.
High · Incorrect domain mapping

staticcheckCategory maps SA (correctness) codes to Style

cmd/go-finding/internal/detectors/staticcheck.go:103-105

Staticcheck's SA codes (e.g. SA1000) are static-analysis correctness checks, but code[0] == 'S' maps them to CategoryStyle. Only ST/S (simplify) codes are style. The test at detectors_test.go:181 asserts the wrong expected value, enshrining the bug.

Fix: Check strings.HasPrefix(code, "SA") → CategoryCorrectness before the single-letter switch. Fix the test expectation.

04Prioritized improvement plan

Ordered by impact-to-effort ratio (Pareto). Each step is independently shippable.

1

Fix the ApplyWithDetails return bug

One-line fix, highest correctness impact. Capture the second return value of ApplyWithShiftMap and return it. Add a test with partial-failure input. Effort: ~30 min.

2

Honest-ify the IntervalIndex

Correct the doc to O(n + k), rename interval_tree.go → interval_index.go, or implement a real augmented tree if scale demands it. Effort: 1-4 hrs.

3

Fix the lying names & predicates

IsValid → require Line>0 or rename HasFile; columnAdjacent→columnCoincident; FilterInvalid→IsInvalid; IsAutoFixable call NormalizeFixStrategy. Effort: ~2 hrs.

4

Use FilePath in Position + export registry errors

Change Position.File to FilePath; export ErrDetectorRegistered/ErrUnknownDetector. Non-breaking additive + a JSON-transparent type change. Effort: ~2 hrs.

5

Plug the silent-data-loss paths

SARIF: emit suppressions arrays; handle multiple fixes. LSP: persist original ID in a property bag. Document every lossy field explicitly. Effort: ~1 day.

6

CLI robustness pass

Add signal.NotifyContext; check output Close() errors; error on unknown detectors; validate format at parse time. Effort: ~2 hrs.

7

Concurrency & consistency fixes

Lock file_backup.enabled; fix PrettyJSONFiltered TOCTOU; unexport or document Report.Tool/Summary. Effort: ~3 hrs.

8

Data-model consolidation

Resolve the Category/Tags split-brain; unify the conflict-detection paths behind one interface; centralize the three severity conversions onto the Severity type. Effort: ~2 days (design first).

9

Performance: cache & index

Cache resolved root in groupFindingsBySafePath; build a file index in gotoken; O(N) frontier for conflict lookup; add an index to FindByID if used at scale. Effort: ~1 day.

10

Reduce global mutable state

Inject severity-alias & linter registries where feasible; add test-reset helpers; extract a CommandDetector[O] generic to dedupe govet/staticcheck. Effort: ~1 day.
