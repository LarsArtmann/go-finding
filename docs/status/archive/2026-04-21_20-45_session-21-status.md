## Top #1 Question I Cannot Figure Out Myself

### Position.Offset Sentinel Design Decision

**Problem:** The `Position.Offset` field uses `-1` as a sentinel value for "unset", but Go's zero-value for `int` is `0`. This creates ambiguity:

```go
type Position struct {
    Offset int  // -1 = unset, 0+ = valid offset
}
```

**Issues:**

1. `Offset: 0` is a valid file offset (beginning of file)
2. `Offset: -1` represents "unset"
3. `Offset: 0` also appears "unset" because `HasOffset()` checks `>= 0`

**Options:**

1. **Keep current design** — Document the convention, add validation
2. **Change to `*int`** — `nil` = unset, `0` = valid
3. **Change to `uint`** — `0` = unset, `1+` = valid

**Why I can't decide:**

- Option 2 is most type-safe but requires API change
- Option 1 is pragmatic but error-prone
- Option 3 breaks existing usage where `Offset: 0` is used as "has offset at start"

**Request:** Please advise on preferred approach. This affects the Position type semantics across the entire library.
