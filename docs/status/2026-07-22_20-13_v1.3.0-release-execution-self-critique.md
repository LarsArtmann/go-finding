## e) WHAT WE SHOULD IMPROVE

### Process Improvements

1. **Disable or configure the auto-commit hook during active editing sessions.** It destroys commit history quality. Every intermediate state gets committed with a generic message. Either disable it, or make it batch commits logically.

2. **Check git status after every edit batch.** The hook fires silently. I should have been watching.

3. **Read .golangci.yml before adding nolint comments.** If I had checked the golines max line length setting, I would have known to keep comments short.

4. **The plan had 71 tasks but I didn't track dependencies carefully.** Some tasks were executed out of dependency order (e.g., I updated FEATURES.md for Template before verifying the rename compiled). This worked because the changes were independent, but it's sloppy.

### Code Quality

5. **The nolint comments are band-aids.** The exhaustruct linter flags legitimate patterns (zero-value returns, builder factory structs). The real fix would be to configure exhaustruct to exclude these types in `.golangci.yml`, but that's a bigger change. For now, nolint is acceptable.

6. **FormatTextRich duplicates ~80% of FormatText.** Both functions iterate findings, format position + rule + message, handle suggestions. The only difference is severity formatting (tag vs badge) and category display. A shared internal function with a "rich" bool would reduce duplication. But the current approach is clearer for consumers.

7. **The `finding_builder_test.go` test names changed from `TestFindingTemplate_*` to `TestTemplate_*` but the test bodies weren't updated to reflect the rename in comments or variable names.** Minor — tests still pass and are correct.

### Documentation

8. **API_STABILITY.md tables are stale.** They don't list Template, SimpleFixResult, FormatTextRich, or any v1.3.0 functions. The version header was bumped but the content wasn't.

9. **CONTRIBUTING.md project tree is still incomplete** — missing ~10 files. A full tree refresh is needed.
