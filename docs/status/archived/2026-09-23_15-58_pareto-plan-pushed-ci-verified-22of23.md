## e) WHAT WE SHOULD IMPROVE

1. **Treat tool-error responses as hard stops** — an edit that reports "modified since read" must be re-read and re-applied before ANY next action; a silent no-op write in a docs pipeline is a future ghost.
2. **After any `git mv`, run the exact CI link-check script locally** (it's an inline block in ci.yml — extract-and-run costs seconds). Better: add it to the docs-gates bundle or scripts/ so it's one command.
3. **Reconcile local-vs-CI lint versions** — a "0 issues" local claim that CI contradicts means the lint gate has an environment split; pin and print the golangci-lint version in both places.
4. **LSP distrust rule** — after multi-tool edit sequences, verify with `go vet`/tests before reading project diagnostics; restart the LSP instead of arguing with its cache.
5. **`date` as literal step 0** — make it muscle memory, not an instruction-driven afterthought.
6. **Ask for (or use) authorized curated commits for every code fix** — this segment had push authorization; the lint fix should have been its own detailed commit instead of riding a daemon heuristic batch.
7. **Pre-push gate bundle** — flake check ran, but the CI link-check and per-module lint didn't; a tiny `scripts/pre-push-verify.sh` (flake check + link check + lint ×5) would have made run 35864784734 fully green on arrival.
