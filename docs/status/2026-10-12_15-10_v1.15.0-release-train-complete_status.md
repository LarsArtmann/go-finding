## e) WHAT WE SHOULD IMPROVE

1. **Gate-awareness before editing release files.** 30 seconds of "which gates read the bytes I'm about to change?" (lychee → CHANGELOG links, docs-api-check → README stamps) would have prevented 2 of 4 wasted CI cycles. Concrete: add a "files-to-gates map" to `docs/release-procedure.md`, and/or build c-7 so the machine catches it pre-push.
2. **Verification hygiene: read what the check ACTUALLY did.** d-3 is the 2026-09-08 "dead gate" lesson in a new costume — a verification that passes against the wrong version is worse than no verification. Rule for agents: after any multi-step verification, re-read the resolution/output lines and name WHAT was verified before believing the verdict.
3. **Push → verify → tag ordering.** Gates with preconditions on pushed state (preflight unpushed check, lychee on published links, CI on the SHA) belong AFTER the push; encode the ordering in the procedure instead of letting each train rediscover it.
4. **Detached long gates.** Stress/bench should run under `nohup … > log 2>&1` with a verdict line, polled read-only; an interrupted poll must never kill a 30-minute gate.
5. **Encode the repo's real release policy.** The generic "never tag on red" rule and this repo's phased flow are in permanent conflict. Owner decision (g-Q1), then: phase-aware gates (c-5) OR documented exception in release-procedure.md — either way, stop re-litigating per train.
6. **Consolidate scattered release knowledge.** AGENTS.md now carries v1.14.0 lessons + v1.15.0 lessons + the 2026-10-01 preflight note + the 2026-09-23 tag-push note — four overlapping war stories. Distill procedure into `docs/release-procedure.md` (single source), leave one-line pointers in AGENTS.md; schedule a gotchas diet pass per the 2026-09-08 archive pattern.
7. **Lychee needs a token.** Anonymous runner IPs + ~30 fresh github.com links per train = periodic 429/502 flakes that cost a rerun cycle every few trains. `GITHUB_TOKEN` input on the lychee action is a one-line fix (c-4).
8. **Compensating controls belong in the checklist or the code.** "Run toolsdk manually because the script skips it" failed exactly as predicted — fix the script (c-6), don't keep a mental note.
