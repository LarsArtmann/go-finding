## e) WHAT WE SHOULD IMPROVE

1. **`version.go` should be bump-verified in CI.** It was stale for an entire release cycle (v1.1.0 shipped claiming to be v1.0.0). A CI check comparing `git describe --tags` against `finding.Version` would catch this. This is the highest-value improvement from this session.

2. **The release-procedure.md is outdated.** It references `version.go` but says "if needed" — it should be mandatory for every release. It also uses `git checkout -b release/...` which violates the global "never git checkout" rule. The procedure should use `git switch -c`.

3. **`ROADMAP.md` staleness went unnoticed.** It said "0.9.1 / pre-v1.0" through v1.0.0 and v1.1.0. Consider a docs-freshness CI check or adding ROADMAP to the BuildFlow doc-age check.

4. **No automated release CI.** Releases are fully manual. A GitHub Actions workflow triggered by tag push (publishing the tag, creating a GitHub Release from CHANGELOG, optionally GoReleaser) would reduce toil and human error.

5. **CHANGELOG `[Unreleased]` discipline.** The `[Unreleased]` section was empty — all v1.1.0 work was already moved to `[1.1.0]`. Good. But the 3 commits since v1.1.0 (lockutil, test defrag) had no changelog entries until I wrote them retroactively. Consider a CI check or hook that enforces CHANGELOG entries on `feat:`/`fix:` commits.
