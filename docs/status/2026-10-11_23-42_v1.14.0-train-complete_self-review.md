## e) WHAT WE SHOULD IMPROVE (structural, this session's lessons)

1. **Aggregate structural-checks in CI** — run every sub-check and report all failures (as preflight does) instead of GitHub's skip-after-first-failed-step; one red hid another for days.
2. **preflight `--target <module>` mode** — derive targets from the module being released, not always core's version.go; eliminates the lockstep false positives that made this train's preflight verdict require manual accounting.
3. **Consumer-proof step in preflight** — clean-dir proxy resolve + build of the tag commit against _published_ siblings; the `replace => ../` masking class (RunDetect landmine) is systemic and currently invisible to every gate.
4. **Load guard for local benches** — refuse or annotate bench captures when load average exceeds a threshold; record evidence alongside the verdict.
5. **Bump-in-tag verification** — `git show <tag>:version.go` before pushing core tags (now in the procedure; would have prevented the 1.13.0-self-report defect).
6. **cmd-tag-at-resync as the standing order** (now in the procedure; ends one-engine-stale CLIs).
7. **Daemon-aware commit protocol** — status→author→add+commit in one chain, post-commit verification; consider batching doc edits to reduce daemon-interaction surface.
8. **vendorHash extraction helper** — script that pulls the `got:` hash from `nix build` output.
