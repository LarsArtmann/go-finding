3. **The quality gate is not optional** — I knew lint was clean before the `.golangci.yml` edit, but I didn't verify after. The broken state was discoverable in 3 seconds.

### Architecture observations (from research, not yet acted on)

4. **All enums are string-based** — `Severity`, `Category`, `FixStrategy`, `Tag`, `SuppressionKind`, `RelationKind`, `ErrorCategory` are all `type X string`. This is Go-idiomatic but allows invalid values at construction time (any string is assignable). Closed enum types (int-based with typed constants) would make invalid states unrepresentable, but would be a v2.0 breaking change. Current approach is fine for v1.x.

5. **Position sentinels are fragile** — `OffsetUnknown = -1`, Line/Column 0 = "not set". The zero-value `Position{}` has Offset=0 (valid byte 0), making `Position{}` not truly "zero." An `Option[T]` or dedicated `OptionalPosition` type would be cleaner but is v2.0 scope.

6. **24 exhaustruct nolints across 12 files** — These signal that exhaustruct is over-aggressive for struct literal construction in a data-heavy library. The `.golangci.yml` exclusion list approach (in progress) is the right architectural fix, not inline nolints.

7. **FormatText and FormatTextRich still share structure** — The refactoring extracted `writeSuggestionLine` but both functions still have identical loop skeletons. A full `formatTextLike(w, findings, opts)` with a formatting options struct would eliminate more, but the current extraction is a good first step that keeps the API simple.
