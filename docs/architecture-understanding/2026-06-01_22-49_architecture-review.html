Open Recommendations

1. PipelineResult.Stable → typed enum

Worth exploring

Problem: Stable bool loses information — false could mean "max iterations" or "cancelled".

Solution: Replace with type CompletionReason string with constants ReasonStable, ReasonMaxIterations, ReasonCancelled.

Files: pipeline/result.go, pipeline/pipeline.go

2. Extract correlation score from Confidence

Worth exploring

Problem: Correlation.Confidence reuses Confidence type for "correlation strength" — different domain concept.

Solution: Define type CorrelationScore float64 for correlation-specific scoring.

Files: merge.go

3. Report.Findings public slice mutability

Strong

Problem: Report.Findings is a public slice — external code can bypass mutex and corrupt state.

Solution: Make findings unexported. Provide All() iterator, FindByID(), AddFinding() as the only access paths.

Files: report.go — breaking change, requires migration

4. FixStrategyAI — commit or remove

Worth exploring

Problem: FixStrategyAI and NeedsAI() are published API with zero backend — vapor surface.

Solution: Either implement the AI integration or remove the constant. YAGNI until there's a consumer.

Files: fix_strategy.go

5. FileBackup TOCTOU in Backup()

Worth exploring

Problem: Backup() calls os.ReadFile then os.Stat — file can change between calls.

Solution: Use os.Open + file.Stat() + io.ReadAll from single file handle.

Files: pipeline/file_backup.go

6. Tag/Category overlap — split brain risk

Speculative

Problem: TagSecurity and CategorySecurity represent the same concept in two type systems with no structural link.

Solution: Document the relationship or merge into a single taxonomy where Tags are a superset.

Files: tag.go, category.go

7. Position.IsValid allows Line=0

Speculative

Problem: IsValid() only requires File + non-negative Line/Column, but Line=0 is "not set" — a position with just a file is considered "valid".

Solution: Consider renaming to HasFile() and making IsValid() require HasLocation().

Files: position.go

8. SARIF Metadata namespace collision

Worth exploring

Problem: Export dumps user Metadata into SARIF properties without prefix — could collide with go-finding/* keys.

Solution: Prefix user metadata with go-finding/meta/* on export.

Files: sarif_export.go, sarif_import.go

9. CLI format string unvalidated

Worth exploring

Problem: CLI -format flag is a raw string — unknown formats silently fall through to text.

Solution: Define type OutputFormat string with constants, validate in flag parsing, error on unknown.

Files: cmd/go-finding/main.go, cmd/go-finding/config.go

10. Batch metrics recording

Speculative

Problem: applyDirectFixes calls RecordFix() N times in a loop — N mutex acquisitions.

Solution: Add RecordFixes(n int) batch method.

Files: pipeline/metrics.go, pipeline/pipeline_detect.go

11. Merge free function vs Report.Merge method

Speculative

Problem: Same name, different semantics — Merge(reports, opts) creates new report with dedup; Report.Merge(other) concatenates without dedup.

Solution: Rename free function to Combine or Union.

Files: merge.go, report.go

12. GeneratedFilter missing context cancellation in hot loop

Worth exploring

Problem: GeneratedFileFilter.Process() checks context only via slog, not for cancellation — can't abort mid-filter.

Solution: Add if ctx.Err() != nil { return nil, ctx.Err() } in the per-finding loop.

Files: pipeline/generated_filter.go

Modularization Assessment

Recommendation: Do NOT modularize. The project has 4 packages, ~27K lines, is a library (not an application), and the root package is the core type system that everything else depends on. Modularization would add overhead with no clear benefit. The "When NOT to Modularize" criteria score: 3+ High signals (small project, no external consumers, all packages change together).

Top Recommendation

Tackle #3 (Report.Findings encapsulation) first — it's the only remaining design flaw that could cause real bugs in production. The rest are quality-of-life improvements that can be addressed incrementally.
